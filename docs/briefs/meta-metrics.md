# Meta metric catalogue expansion — shared implementation contract

User wants every available Meta API metric in the builder selector, not the three hard-coded measures; tables should permit multiple selected metrics. Preserve auth, server account bindings, legacy documents and existing non-builder dashboard responses.

## Evidence already probed by parent (no secrets for workers)
Graph v26.0 authorized pilot at campaign level returned spend/impressions/clicks + reach/frequency/cpc/cpm/ctr/inline_link_clicks/inline_link_click_ctr, actions, action_values, cost_per_action_type, conversions, conversion_values, purchase_roas and video action arrays. Values are strings. Custom conversion types include dot-separated custom names. `default_summary=true` returned all requested aggregate fields in `summary` including reach, rates, costs and arrays. Missing value is not zero. SDK v26.0.2 field registry has been downloaded verbatim as `lib/meta-insights-fields.json` (public source URL included).

## Shared interfaces (do not rename)
`lib/meta-metrics.ts` exports:
- `type MetaMetric = { id:string; label:string; group:string; field:string; actionType?:string; format:'number'|'currency'|'percent'; additive:boolean; scale:number }`.
- `BASE_META_METRICS: MetaMetric[]`: catalog of safe scalar numeric candidates from SDK plus seeded well-known action/video metric IDs. Text dimensions, IDs, rankings, arbitrary objects and histogram arrays are not numeric measures and must be excluded and documented. Unknown specialized numeric scalar names may keep exact API ID as label rather than guessing meaning.
- `META_DISCOVERY_FIELDS: string[]`: ['actions','action_values','conversions','conversion_values','cost_per_action_type','unique_actions','cost_per_unique_action_type','purchase_roas','website_purchase_roas'] (plus seeded static video action families do not require discovery up front).
- `getMetaMetric(id:string): MetaMetric | undefined`: strict SDK allowlist scalar IDs or `<allowed AdsActionStats field>:<action_type>`; action_type limited to 180 chars and /^[A-Za-z0-9_.-]+$/, forbid prototype keys. Never accept arbitrary API field/path/account overrides. Provide labels including the exact action subtype so distinct conversions are not merged.
- `discoverMetaMetrics(rows:Array<Record<string,unknown>>): MetaMetric[]`: discovers every returned AdsActionStats subtype (no summing families); merge/dedupe/sort with BASE metrics for result catalogue. Bound action catalog 1500 to avoid unbounded upstream payload. Do not seed every possible action under every family; use common actions and all documented video arrays with video_view where appropriate.
- `format='percent'` values normalize to FRACTIONS (scale .01 for API percentage-point fields like ctr); currency for costs/value/spend, numbers for ROAS/frequency/seconds. Additive false for reach/unique/rates/frequency/cost/ROAS/averages, conservative default false.

New connector `lib/integrations/meta-builder.ts` exports `readMetaBuilderInsights(input)`; input same account/start/end/level/token/allowedAccountIds/fetchImpl as existing connector plus `metrics?:string[]`, `discover?:boolean`.
- Returned envelope matches existing MetaInsightsResult keys, with rows containing existing camelCase identities + core spend/impressions/clicks and requested metric IDs -> finite number|null; `totals: Record<string,number|null>` from API summary, never sums unique/rate/ROAS across rows; `metrics: MetaMetric[]` = catalogue; `unavailableMetrics:string[]`; warnings and partial status as needed.
- Only approved SDK field names form upstream fields. Identity stable IDs included and matched per row. Request only desired fields plus core/identity, and discovery families only when discover=true. Token in Authorization only. No browser token or direct account selection. Truncate/pagination safely (same five-page limit), bounded timeout. Split requests into field groups (~12) with row-ID merge. For per-field code100 unsupported-field failures isolate/retry individual fields within bounded budget (not permission/rate errors); keep unrelated base metrics usable and explicitly null/error missing selected field. Do not silently return successful numbers for failed field queries. Do not fetch graph-supplied next URLs; use validated cursor on fixed origin. Sanitize exceptions.
- Use default_summary=true. Summary unavailable -> null for nonadditive metrics; warning. Additive totals may only fallback if complete rows, all present; easiest leave summary totals null if absent.
